# MPFB2 mesh analysis — frozen method (written BEFORE any computation)

Scope: only the 10 approved MPFB2 files in /workspace/research/reflib_v1/mpfb2/ (commit 6ff1eb35…, v2.0.18).
Tools: python3 stdlib + numpy. No Blender, no installs, no downloads, no writes outside this folder.
Before/after: sha256 of all 10 files (+ MANIFEST) taken before and after; must be identical.
Only exploratory peeking done before freezing: `head` of base.obj, key/strategy tallies and one sample entry from each JSON, and line counts of v/vt/f/g (to learn the file formats).

## M1 OBJ parse
Count `v`, `vt`, `vn`, `f`, `g`, `o`, `s`, `usemtl`, `mtllib` lines. Face arity = number of vertex refs per `f` (tri/quad/ngon>4). Face refs are `v/vt`; 1-based -> 0-based. Group of a face = last preceding `g` name. Repeated group names are merged (number of segments reported). Group vertex set = unique v indices referenced by faces of that group (an OBJ group holds faces, not vertices).
## M2 Weights vs OBJ
For each weights file: `weights` = {bone: [[vertex_index, weight], ...]}. Report: bones, entries, min/max index, unique indices, out-of-range (<0 or >= nv), duplicate (bone,idx) pairs, vertices with no entry ("unweighted"), per-vertex weight sum (min/max/mean, count |sum-1|<=1e-3, >1.001, <0.999, and sum==0), influences per vertex counted three ways: all entries; entries with w>1e-6; entries with w>1e-3 (max, mean over weighted vertices, mean over all nv). Unweighted and weighted vertices broken down by OBJ group. Bone names in weights vs bone names in the matching rig json (set difference).
 Matching: standard/weights.default.json <-> standard/rig.default.json; standard/weights.game_engine.json <-> standard/rig.game_engine.json; rigify/weights.human_toes.json <-> rigify/rig.human_toes.json.
## M3 Topology
Over (a) whole mesh, (b) faces of group `body` only, (c) each group: unreferenced vertices; union-find connected components (via shared vertices); undirected edge -> adjacent-face count => boundary (1), manifold (2), non-manifold (>=3); also edges with inconsistent winding (same directed edge used twice); valence = number of unique neighbours per vertex; distribution of valence, poles (valence 3, 5, >=6 for referenced vertices), quad-only valence-4 fraction; vertex/vt split counts (unique (v,vt) pairs vs v); UV range and count of faces with UV. Symmetry: for body-group vertices, mirror x -> -x, nearest neighbour distance to any body vertex (chunked brute-force numpy); report counts within 1e-4, 1e-3, 1e-2, 1e-1 OBJ units, max/median residual, and number of vertices with |x|<=1e-4 (centre line). Also whether index pairing exists (nearest mirror index) is reported as the nearest-neighbour map, not assumed.
## M4 Joint groups
For each rig json (default, game_engine, rigify human, human_toes) tally head/tail strategies (CUBE/VERTEX/MEAN/XYZ). For each CUBE `cube_name`: does an OBJ group of that name exist, number of vertices, overlap of its vertex indices with `body` group vertices, index range. For each `vertex_index` / `vertex_indices`: which OBJ group(s) contain the vertex, index range. Report whether joint groups are separate helper vertices or body vertices.
## M5 Coordinate convention (independent of CAD Bro)
Reconstruct positions from OBJ: CUBE = mean of group vertices; VERTEX = v[vertex_index]; MEAN = mean of v[vertex_indices]. Compare with `default_position` under all 48 axis-permutation/sign hypotheses with free scale s and translation t fitted by least squares (scale = fit); report best hypothesis + residual, and residual of the hypothesis "rig=(x,-z,y)*0.1" specifically; report 2nd-best residual. Evidence level: MEASURED fit; the "Blender Y-up->Z-up import, decimetre->metre" label is INFERRED from the winner.
